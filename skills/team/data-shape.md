# 資料的形狀

決定一組資料該用什麼型別傳：rd 實作、sa 審查、pm 盤點時讀。專案的語言構造與例子寫在該 repo 的 `AGENTS.md`，本檔只給判斷。

- **要找的味道**：Data Clumps（同一組欄位總是一起出現）與 Primitive Obsession（用陣列、字串頂替領域概念）。修法是 Introduce Parameter Object／Encapsulate Record，收成不可變的 Value Object，讓欄位缺漏、改名與型別錯由語言擋下。
- **跨邊界被讀才收**：別的類別按名稱讀欄位，或按位置取出兩個以上同型別的值（對調時型別檢查照樣通過）時收成物件。只在同一類別內產生又讀取的維持原樣，只有一個欄位的直接傳純量——KISS，換得到型別保護才多一個型別。
- **Make illegal states unrepresentable**：成對、互斥、非空這類規則放進型別或建構子；型別說不出來的才留給執行期檢查。
- **Parse, don't validate**：形狀由別處定的——API 回應契約、第三方回應、資料庫列、框架規定的回傳——照對方的形狀留在邊界，在邊界轉換一次。
- **一個概念一個型別**：產出端與讀取端同一次改完；欄位看起來一樣、意思不同的各自一個型別。
