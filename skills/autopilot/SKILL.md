# autopilot

使用者呼叫這支 skill，就是把後面那件事整串交給開發團隊：主 session 是 `${CLAUDE_PLUGIN_ROOT}/agents/rd.md` 裡的**上層**，照它推到底。先讀 `${CLAUDE_PLUGIN_ROOT}/skills/team/SKILL.md`；下文的「檔名〈節名〉」指 repo 裡的檔。下面的授權都來自這一次呼叫。

## 授權範圍

- **挑票與派工**：照 rd.md〈一、A〉挑好票號，每個 `devteam:rd` 只交辦「實作 #N」；彼此不阻擋、不碰同一塊的票各開 worktree 平行交辦。
- **代定**：triage、範圍釐清（縮範圍除外）、標籤，以及角色建議開的後續票，照 team〈推薦選項的判準〉與 `issue-tracker.md`〈什麼該變成票〉代定。上層自己把結果寫進票的留言（標明「維護者授權代定」與理由）並改標籤；子代理不把上層轉述的授權當成使用者點頭。代開的票不算進這一次的交辦範圍。
- **接手回報**：關卡與定案歸 `rd`。回報裡還有未定案的 finding 就交回 `rd`；上層自己改了碼，從 rd.md 第三節第 3 步起重走受影響的關卡。
- **合併**：一次合一個，指令照 `dev-workflow.md`〈分支、commit 與合併〉。合併前確認第三節第 4 步的讀數是在目前的主線上跑的；主線動過就交回 `rd` 併入主線、照第三節重跑受影響的關卡，再合。合併後讓 `rd` 收票。沒有票的入口 B，上層替那條分支開 PR，同樣走接手回報與合併。

## 停點

team〈每個角色都照做〉裡只有使用者能決定的那兩件事（縮範圍、不可逆的改動）照樣停，`AGENTS.md` 另外列的停點也一樣。決定題用 `AskUserQuestion` 出成選擇題：每個選項寫明後果，推薦的放第一個並標「（推薦）」。平行中撞上停點時，其他不受影響的票先做完，再一起問。

## 完成與回報

交辦範圍內每一張票都已合併並關閉、被還沒解開的阻擋擋住，或缺只有人補得出的東西，才回報一次：合了哪些 PR（畫面改動附截圖的絕對路徑）、關了哪些票、代定了哪些取捨、代開了哪些票、還有什麼沒做與為什麼。
