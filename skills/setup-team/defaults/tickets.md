## 什麼該變成票

審查與實作途中的發現預設不開票，照順序判斷去處：

1. **當場修掉**：不改公開契約（對外的型別、API、保存格式、CLI）、不需要新增測試、小到寫票比改還貴——三條都成立就改在手上的 diff 裡，commit 訊息帶一句。不確定算不算就是不算。
2. **開票**：滿足任一條。
   - 擋住一張已經決定要做的票（寫出哪一張）。
   - 對應一個已經觀察到的使用者可見錯誤行為（寫重現步驟或實際輸出，不是推論）。
   - 是母票驗收區明文列出的項目（寫出母票與哪一項）。

   「使用者」是 `AGENTS.md` 說的產品使用者，不含維護者：測試穩定性、殘留暫存檔、覆蓋率缺口傷的是跑測試的人，不記；哪天真的擋住一次合併，改走第一款。

3. **其他不記**，尤其是「X 沒有判準／讀數／守門測試／型別上擋不住」——要變成票必須指出一個因為缺它而實際漏掉的錯誤行為。

代理不自己開票：把需要開的票列給使用者，標題用 `CONTEXT.md` 的詞，逐項標明過的是哪一條，過不了的標「不記」。

已經開出來的票過不了門檻時，以 `gh issue close --reason "not planned"` 關掉，不掛 `wontfix`，留言寫過不了哪一條、缺什麼、什麼條件成立該重開。拒絕一個請求時，理由寫在關票留言，不另建紀錄。

## Definition of Done

PR 合併之後才走；合併前只把證據補到票上，不勾驗收、不關票。

1. 跑完驗收所需的檢查，確認票的範圍全部交付。
2. 驗收區（`## 驗收` 底下的 checkbox）每一項有直接證據才把 `- [ ]` 改成 `- [x]`，用 `gh issue edit <n> --body-file <file>` 更新全文；不改驗收項目的文字與驗收區以外的內容。仍有未勾項時票保持開啟，回報缺什麼。
3. 留完成摘要：commit、完成的行為、逐項驗收證據、檢查結果、沒修的審查 finding 與理由、仍需揭露的限制。
4. 拿掉接手標籤，關票。接手只用 assignee 表示時，這一步只關票。
5. 讀回內文與狀態，確認驗收全部 `[x]` 且狀態是 `CLOSED`，才回報完成。

母票等所有子票關閉、完整範圍交付後才留言並關閉。
